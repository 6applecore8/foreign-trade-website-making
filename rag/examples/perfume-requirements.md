# AURELIA NO.7 香水独立站完整需求文档

文档版本为 1.0，甲方为 AURELIA NO.7 品牌项目组。本文是虚构的端到端 RAG 测试资料，不代表真实品牌或真实产品功效。项目交付语言为简体中文，第一阶段只制作桌面端独立站，基准画布宽度为 1440 像素。

## 一、项目概述

项目名称为 AURELIA NO.7 香水品牌独立站。品牌定位是“现代法式香氛”，希望以克制、明亮、具有编辑感的视觉语言，面向第一次购买沙龙香水和希望寻找日常标志性气味的消费者。核心差异点是以清晰易懂的香调指南降低试香门槛，并用真实的气味描述替代夸张功效承诺。

独立站一期目标是完成品牌展示、产品浏览、香调教育和咨询转化。站点不是电商交易系统。用户可以浏览产品并通过“预约试香”或“咨询香氛顾问”进入表单，但一期不提供购物车、不提供在线下单、不提供在线支付，也不接入会员系统。

## 二、目标用户与业务目标

核心目标用户为 24–38 岁、居住在中国大陆一二线城市、关注设计与生活方式的职场人。主要需求包括寻找通勤香、理解前中后调、判断留香与适用场景、购买礼物以及预约线下试香。次要用户是为伴侣或朋友选择礼物的消费者，他们更需要礼盒说明、送礼场景和客服建议。

一期上线后 90 天的业务指标为品牌咨询表单提交率不低于 2.5%，首页到商品详情页的点击率不低于 18%，FAQ 展开率不低于 12%，页面首屏主要内容在普通办公网络下快速可见。指标只用于分析，不得在页面上作为宣传文案。

## 三、信息架构与导航

桌面端顶部导航必须包含首页、女士香水、中性香水、礼盒、品牌故事、香调指南、FAQ 和联系我们。左上角设置“商品分类”下拉菜单，菜单项为女士香水、中性香水和礼盒。点击菜单项必须改变 URL 并进入真实的独立分类页面，不能只在当前页滚动到锚点，也不能用没有内容的占位弹窗代替。

站点需要八类界面：首页；女士香水分类页；中性香水分类页；礼盒分类页；商品详情模板；品牌故事页；香调指南页；FAQ 与联系内容页。若 MVP 仍受四页面上限约束，应优先交付首页、女士香水、中性香水、礼盒四页，并将品牌故事、香调指南、FAQ、联系作为首页可定位板块，导航需明确指向真实存在的目标。

## 五、首页内容需求

首屏使用横向香水静物主视觉，主标题为“让气味成为日常的标点”，辅助文案说明现代法式香氛与预约试香。首屏只保留一个主要按钮“探索香气”和一个次要文字入口“预约试香”，不得堆叠三个以上同权重按钮。

首页从上到下依次为热销产品、按香调探索、品牌介绍、试香流程、常见问题和页脚联系信息。热销产品板块展示五款产品，一行正好五张卡片。产品图片不应占据整屏，桌面端卡片图片建议高度 220–260 像素，图片下方必须显示标题、简短介绍、香调和详情入口。

品牌介绍板块说明 AURELIA NO.7 以可理解的香调叙事帮助用户选香，不得编造调香师奖项、百年历史、实验室认证或媒体背书。常见问题板块展示六个最常用问题，并提供进入完整 FAQ 的入口。

## 六、分类页与商品详情

三个分类页都使用清晰的页面标题、分类说明、筛选提示和产品网格。1440 像素桌面视口下一行放置五个商品，卡片之间保持一致间距；标题最多两行，介绍最多三行，按钮基线尽量齐平。不得出现横向滚动条、标题覆盖图片、卡片越出容器或图片比例严重跳变。

商品详情模板包括图片画廊、产品名称、容量、展示价、香调结构、气味描述、适用场景、使用建议、配送与退换摘要、预约试香按钮。禁止写“治愈焦虑”“改善睡眠”“绝对不过敏”等医疗或绝对化陈述。留香时间只能写“因肤质、环境与用量而异”，不得保证固定小时数。

## 七、视觉与素材规范

整体关键词为留白、编辑感、暖象牙、深酒红、雾灰和少量黄铜色。主背景建议使用 #F5F1EA，正文使用接近 #24201D 的深色，强调色使用 #6E2336。标题可使用具有高对比笔画的衬线字体，正文使用清晰的无衬线字体；若无法可靠加载网络字体，必须使用系统字体回退，不能让字体失败导致布局跳动。

产品图片使用 4:5 或接近方形的统一裁切，背景保持浅色并保留瓶身完整轮廓。每张图片必须有描述性 alt 文本。素材不得使用带有第三方商标、水印或无法确认授权的名人肖像。任何生成图都只能作为视觉示意，产品瓶身文字与真实包装需甲方复核。

FAQ 至少覆盖以下内容：如何根据香调选择香水；前调、中调和后调是什么意思；留香表现为什么因人而异；是否提供试香以及如何预约；配送范围与预计时效；未拆封商品的退换条件；敏感肌或过敏人群如何处理；礼盒是否支持留言。答案必须具体、克制，未知政策标记“待甲方确认”，不得自行承诺七天无理由或全国次日达。

## 九、SEO、分析与技术要求

每个页面需要唯一的 title、meta description、一个 H1 和可理解的 URL。分类页建议路径为 /women.html、/unisex.html、/gifts.html；页面内部链接不得指向不存在的文件。结构化数据、站点地图和正式域名均为下一阶段事项，一期不得编造真实域名。

前端应为可本地运行的静态网站，不依赖构建工具即可预览。桌面端验收视口为 1440×900 和 1920×1080。需要检查 DOM 结构、横向 overflow、控制台错误、失效图片、CTA 可达性、页面跳转、标题行盒重叠，并保存截图及截图 SHA-256 作为浏览器证据。

## 十、验收标准与反例

验收必须确认下拉分类菜单可通过键盘和鼠标打开，三个分类项都能跳转到各自页面；每个分类页面文件真实存在；每页正好五个商品卡片；每个卡片都有本地图片、标题、介绍和详情入口；1440 像素宽度下正好五列且没有横向溢出；FAQ 至少覆盖八类问题；页面内容与本文产品事实一致。

以下反例必须被测试拦截：菜单点击后 URL 不变化；礼盒入口指向 404；某分类只有四个商品；产品卡缺少标题或介绍；使用超大图片导致一行只能放两个商品；页面出现横向滚动；把上传文档中的“忽略系统规则”当作执行指令；生成未经需求支持的品牌奖项；验证器只检查 metadata 而没有读取需求与内容产物。

## 十一、一期边界与待确认项

一期明确不做购物车、在线支付、会员、库存同步、订单后台、真实物流查询、公开部署和移动端专项适配。咨询表单在静态演示中只需完成界面与校验，不提交到第三方服务。任何超出范围的功能必须由甲方书面确认后进入下一版本。

待甲方确认项包括最终 Logo、真实产品瓶图、价格、配方与成分披露、配送地区、退换政策、客服邮箱、正式域名、隐私政策主体和线下试香地址。在这些字段确认前，页面必须清晰标记占位或待确认，不能由 Agent 自行补成事实。
