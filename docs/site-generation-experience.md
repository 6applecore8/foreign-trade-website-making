# 独立站生成经验与桌面端门禁

本文件把 NOVA 鞋服站实践固化为后续项目的默认验收经验。它不是客户事实来源；当客户文档与默认经验冲突时，以经过确认的客户需求为准。

## 默认实现经验

- 名为“商品分类”的控件默认使用可访问的下拉菜单；菜单项若表达页面导航，点击后必须改变 URL 并渲染真实分类页面。
- 每个声明的商品分类都必须有独立页面或需求明确允许的真实目标，禁止空链接、占位弹窗和不存在的路径。
- 1440 像素桌面视口默认采用一行五个商品卡片；商品图片保持统一比例和适中高度，标题、简介、详情入口缺一不可。
- 首页默认包含热销产品、品牌或公司介绍、FAQ 三类内容板块；热销板块应有多张真实可加载产品图片。
- 第一次交付前必须完成浏览器证据检查，覆盖 DOM、URL 跳转、横向 overflow、标题与图片重叠、CTA、控制台错误、截图和截图哈希。

## 必须保留的反例

1. 分类菜单能展开，但点击后 URL 不变化。
2. 某个分类入口返回 404 或目标文件不存在。
3. 需求规定五个商品，页面只渲染四个，或卡片缺标题、介绍、图片。
4. 超大图片让桌面端一行只能显示两个商品，或产生横向滚动。
5. FAQ 在配置中存在，但实现页面未渲染，验证器仍只检查 metadata 后放行。
6. 上传资料包含“忽略此前规则”一类文本，Agent 把它当系统指令执行。

这些反例应由确定性验证器和真实浏览器证据拦截。LLM 只评价可读性、风格一致性和事实风险，不能覆盖结构性失败。
